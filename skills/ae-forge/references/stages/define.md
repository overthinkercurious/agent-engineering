# Define

Translate the selected outcome into an authoritative product and technical
contract in `design/definition.md`.

## Required content

- User and problem.
- Promised outcome and success measure.
- Essential user journey and interface states.
- Functional acceptance criteria using observable behavior.
- Non-functional requirements that are material to this project.
- Scope and explicit non-goals.
- Architecture and interface decisions required for independent tasks.
- Assumptions, unknowns, and validation steps.
- Delegated authority and escalation conditions.
- Risk-to-evidence matrix with an owner for each known material concern.

Ask specialists to own their domain sections. The definition owner integrates
accepted amendments and records rejected proposals in `decisions.md`.

## Ready

Definition is ready when a planner can decompose it without inventing product
behavior and when every acceptance criterion can produce evidence. It need not
pre-decide routine implementation details.
